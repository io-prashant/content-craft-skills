# Sales Message Playbook

Write short, honest sales messages that move one deal one step. Every draft passes the buyer-perspective review in references/buyer-review.md (pass band 8.5/10) before it is shown or sent.

## When to use

- A prospect chat or email needs a reply, follow-up, or rating.
- Writing a cold DM or cold email to a brand or lead.
- Any "is this message good?" question about a deal.

## Ground before writing

- Work only from the visible conversation and the stated goal. Numbers already on the table - rate, advance, scope, revision count - are settled. Do not move them, waive anything, or promise timelines, results, or free work unless the owner explicitly says so for this message. If a good idea would change terms, present it as an option, not as drafted copy.
- Name the stage first: cold touch, replied lead, samples/quote sent, objection, negotiating, onboarding, or stalled. The stage sets the job of the message. Not every message is a close: sometimes the correct reply to a busy client is a single acknowledging line, and a collection message can end cleanly on the payment ask.
- Inferred buyer motives are hypotheses. They shape tone; they never appear in the message as facts.

## Core principles

1. Value before ask. Offer an idea, evidence, or clarity before you request anything.
2. One message, one job, one ask. Several unrelated asks in one message kills replies.
3. Specific beats polished. A line only this prospect could receive outperforms a template every time.
4. Truth is a hard constraint. No invented clients, numbers, deadlines, scarcity, discounts, or free work. One fabricated claim fails the message outright - it is not a style issue.
5. Follow-ups add new value. Never "just checking in". Each touch brings something: a new angle, a useful observation, a clean binary close.
6. The buyer's words, not yours. Match their language and register (Hinglish for Hinglish chats, formal for corporate).

## Message shape (default, not a straitjacket)

A strong short message tends to do four things in order: a specific line about them (proves this is one-to-one), one useful idea or observation, why now is a fair moment, and one small easy ask. Cold email adds: a personalized subject that references their world, not a sales line; a short body of one idea; a low-pressure call to action ("want the two examples?") instead of a meeting demand; and a compliance footer (opt-out line and real postal address) on commercial sends.

## Stage notes

- Cold first touch: earn the reply, not the deal. One specific observation, one idea, one small question. Data from large outreach datasets points the same way: personalized subjects and first lines, short bodies, and interest-based CTAs beat generic blasts and calendar demands.
- Replied lead: answer their exact question first, then advance one step. Speed matters; same-hour answers qualify far more leads in classic HBR lead-response research.
- Samples or quote sent, then silence: follow up with new value at a calm cadence (a day or two, a week, two weeks), then close the loop with an honest either/or ("Want me to close this file for now? A straight no is completely fine"). A clear no frees both sides.
- Objections: diagnose before answering. "Too expensive" can mean no budget, no seen value, or a procurement rule. Price pushback gets trade-offs (smaller scope, staged payments), not reflexive discounts.
- Negotiation: quoted terms stay fixed unless the owner moves them. Make package trade-offs explicit: when rate, count, and revisions all move, show the whole exchange in one recap so both sides see the same deal.
- Onboarding: congratulate, collect the inputs you genuinely need, state what happens next, and confirm the commercial terms once, plainly. For deals agreed in chat, one recap message covering scope, price, advance, balance due, revisions, and timing - with a written YES - prevents most later disputes.

## Never

- Never invent proof, pressure, guilt, or manufactured urgency.
- Never resend terms you already pitched unless you add something new.
- Never promise a timeline or free work the owner did not state.
- Never stack multiple asks.

## Scope

This skill governs message quality only. Its default output is a draft for the owner to review. Whether anything is actually sent, from which account, and under what authority is decided outside this skill.
